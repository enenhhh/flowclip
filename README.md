# FlowClip

> **由 [恩恩hhh (enenhhh)](https://github.com/enenhhh) 开发**，与其他任何名为 "Flow Clip" 的产品无关。
>
> **小而美**：Windows 端安装包仅约 13 MB（exe 13.1 MB / zip 13.0 MB），Android APK 仅约 89 KB。

一个在手机、电脑之间同步剪贴板、传输文件的免费开源工具。

## 它能做什么？

- **同步剪贴板**：在一台设备上复制的文字或图片，其他设备能直接看到并粘贴使用。
- **传输文件**：在设备之间直接发送文件，不需要经过网盘或 U 盘。

支持 Windows、Linux、macOS 和 Android 四种系统。

## 它是怎么工作的？

FlowClip 采用「一台服务器 + 多台客户端」的结构：

- 选一台**一直在线**的设备当作服务器（四种系统都行）。
- 其他设备作为客户端连接这台服务器。
- 剪贴板内容由服务器转发给所有客户端，文件也通过服务器中转。

几个关键点：

- **完全自托管**：不依赖任何官方云服务，数据只在你自己的设备之间流动。
- **不保存剪贴板历史**：服务器只在内存里保留最新一条剪贴板内容；文件会保存在服务器设备的硬盘上，需要你自己手动删除。
- **默认走局域网**：在可信的局域网内可直接使用 HTTP；要连到外网时，建议配合加密虚拟局域网（如 Tailscale）或 HTTPS 隧道使用，以保证数据安全。

## 支持哪些平台

| 平台 | 剪贴板实现 | 后台入口 | 发布形式 |
| --- | --- | --- | --- |
| Windows 10/11 x64 | 系统原生剪贴板，支持文字和图片 | 系统托盘、开机自启动 | 单个 `FlowClip.exe` |
| Linux x86_64 | Wayland 用 `wl-clipboard`，X11 用 `xclip`；界面需 X11/XWayland | 托盘（可用时）、开机自启动 | `FlowClip` 可执行文件的 tar.gz |
| macOS | 系统原生 `NSPasteboard`，支持文字和图片 | 菜单栏、开机自启动 | `FlowClip.app` 的 ZIP 和 DMG |
| Android 8.0+ | 前台读取文字/图片、系统分享、文件选择器 | 前台服务自动接收、可当手机服务器、开机恢复 | 标准 Gradle 工程 |

> 关于 Linux 的说明：程序需要在带图形界面的 X11 或 XWayland 会话里运行。
> Wayland 需要安装 `wl-clipboard`，X11 需要安装 `xclip`。当前界面和系统托盘
> 仍依赖 X11/XWayland；完全没有 XWayland 的纯 Wayland 会话不支持。
> 如果托盘不可用但主窗口还能打开，程序会保持窗口运行，关掉窗口即退出。

更详细的支持范围见 [平台支持说明](docs/PLATFORM_SUPPORT.md)。

## 主要功能

- **剪贴板自动同步**：桌面端会自动检测本机剪贴板的变化并同步；也可以手动发送或接收。
- **图片统一转成 PNG**：文字用 UTF-8 编码，图片同步时会统一转换为 PNG 格式。
- **灵活的服务器配置**：桌面端可自定义监听地址和端口；Android 可选 `1024`–`65535` 之间的端口，并会显示当前可用的本机 IP 地址。
- **文件传输**：支持列出、上传、下载和删除文件。传输时按原始二进制流处理，不经过 Base64，也不会把整个文件一次加载进内存。
- **断点续传（桌面）**：上传和下载都显示进度且可取消；桌面客户端下载中断后留下的临时文件，可在支持 `Range`、`ETag`、`If-Range` 的桌面服务器上续传。
- **内存与硬盘分工**：剪贴板服务器只在内存里保留一条数据；文件服务器把完成的文件和索引保存到本机硬盘。
- **安全措施**：共享密钥鉴权、请求/响应大小限制、同源跳转限制、公网强制 HTTPS 校验。
- **托盘与开机自启**：桌面端支持系统托盘/菜单栏、单实例运行、跨平台开机自启动。
- **Windows 拖拽上传**：可以直接把文件拖进主窗口或「文件快传」窗口，多个文件会在同一个任务里依次上传。
- **Android 自动接收**：前台服务负责自动接收，也负责维持手机内置服务器；支持从其他应用拖入或分享文字、图片、文件及多项内容。
- **Android 图片保存**：Android 10+ 把收到的图片保存到公共 `Pictures/FlowClip` 目录；Android 8/9 保存到应用专属图片目录。

## 快速开始

下面按「装程序 → 配服务器 → 配客户端 → 选同步方式 → 传文件」的顺序说明。总共只要几步就能用起来。

### 第 1 步：装好桌面程序

从 GitHub Releases 下载对应你系统的版本，或者按 [构建说明](docs/BUILDING.md) 自己编译。注意：用 PyInstaller 打包的程序**必须**在对应的系统上生成——不能用 Windows 交叉编译出 Linux 或 macOS 的版本。

> 关于安全提示：Windows 版如果没有代码签名，下载时可能出现 SmartScreen 提示；
> macOS 版如果没有配置 Developer ID 签名，会触发 Gatekeeper。
> 请先核对 Release 里的 `SHA256SUMS` 校验和，再按系统的「仍要打开」流程操作，
> 不要为了省事关闭整机安全机制。

### 第 2 步：配置服务器

先选一台设备当服务器。

**桌面端当服务器：**

1. 勾选「启用内置服务器」。
2. 局域网服务通常监听 `0.0.0.0`，端口用 `8765`（或任意未被占用的端口）。
3. 保存设置，记下界面显示的局域网地址和随机生成的共享密钥。

**Android 当服务器：**

1. 勾选「将此手机作为服务器」，填一个 `1024`–`65535` 之间未被占用的端口。
2. 保存设置并允许前台服务运行。界面会显示当前的本机 IP 地址，例如 `http://192.168.1.30:8765`。
3. 手机服务器会监听所有可用网络接口，不能在界面里单独指定地址；请用系统网络和防火墙限制访问范围。

同一组设备一般只开一台服务器，并且只向可信网络开放端口。

**关于共享密钥：** 密钥必须是 16–512 个可见的 ASCII 字符，不能含空格、中文或控制字符。它会在每次请求时发送，请像密码一样妥善保管。

### 第 3 步：配置客户端

桌面客户端填一个带端口的服务器地址，例如：

```text
http://192.168.1.20:8765
```

- 桌面端默认允许回环、私网、链路本地以及 `100.64.0.0/10`（如 Tailscale）范围内的 IP 走 HTTP；「公网地址必须使用 HTTPS」默认开启，公网 IP 或任何域名的 HTTP 会被拒绝。
- Android 连局域网 HTTP 时，还需要额外勾选「允许可信局域网 HTTP 明文连接」；公网 HTTPS 校验同样默认开启。
- 所有客户端都必须填和服务器**完全一致**的共享密钥。
- 所有 URL 都要显式带上端口（包括 `https://clip.example.com:443`），且不能包含账号、路径、查询参数或片段。

### 第 4 步：选择同步方式

- 桌面端：开启「自动同步剪贴板」后，应用运行期间会自动发送本机变化并同步服务器；关闭后可用「发送当前剪贴板」和「接收最新内容」手动操作。
- Android：不会在后台偷偷读取或自动发送剪贴板。要发送时，打开 FlowClip 点按钮，或从其他应用的分享菜单发到 FlowClip。
- Android 的「后台自动接收」使用带常驻通知的前台服务，只负责接收，不会绕过系统的剪贴板和后台限制。

> 如果 Android 也参与同步，建议把所有设备单条上限设为 8 MB 或更低。
> 桌面端默认 20 MB、可配 1–100 MB；Android 默认和最高都是 8 MB。

### 第 5 步：传输文件

文件传输和「最新一条剪贴板」是分开的。客户端先提交元数据，再以固定长度流式上传原始字节；下载也直接传原始字节，传完校验大小和 SHA-256。

- 桌面端：默认单文件上限 2048 MB（可配 1–10240 MB）；服务器总配额默认 8192 MB（可配到 51200 MB），最多保留 100 条文件记录。默认服务器目录是 `~/Downloads/FlowClip Server`，默认下载目录是 `~/Downloads/FlowClip`，都可以改成其他绝对路径。
- Windows：可从资源管理器直接拖文件进窗口；多个文件用一个后台任务依次上传。
- Android：默认单文件上限 256 MB（可配到 2048 MB）；手机服务器最多保留 50 条完成与待上传记录（其中待上传最多预留 8 个），没有独立总配额，受设备剩余空间限制。
- Android 10+ 的文件保存到公共 `Download/FlowClip`；Android 8/9 保存到应用专属下载目录（卸载时被系统删除）。注意剪贴板图片用的是 `Pictures/FlowClip`，别和这个目录搞混。
- 断点续传：桌面客户端下载中断会保留隐藏的 `.part` 临时文件以便续传；主动取消会删除它。Android 取消或失败时直接丢弃未完成文件，目前不支持续传。
- 桌面服务器会为完整文件返回 SHA-256 的 `ETag` 和 `Accept-Ranges: bytes`，支持单段 `Range`/`If-Range`；Android 服务器目前只返回完整 `200` 响应，不提供续传，桌面客户端连它会从头重新下载。

## 局域网与公网

FlowClip 内置服务器只提供 HTTP，没有 TLS，也不做端到端加密。所以怎么连，取决于你的使用场景：

- **可信局域网**：直接用私网 IP 和指定端口即可；Android 需要额外确认局域网明文开关。
- **异地组网（推荐）**：优先用 Tailscale、ZeroTier 这类加密虚拟局域网。
- **公网域名**：用 Cloudflare Tunnel，或用只回源到本机的 FRP 通道加 Nginx/Caddy 的 HTTPS 入口。
- **公网 HTTP（不建议）**：关闭客户端 HTTPS 校验只是去掉拦截，并不会加密共享密钥或剪贴板内容。除非已经有明确的外层加密保护，否则不要关。

更完整的拓扑、FRP 边界、防火墙和排错说明见 [部署说明](docs/DEPLOYMENT.md)。

## 后台与开机自启

- **桌面端**：只有程序在运行时才会自动同步。托盘或菜单栏可用时，关掉主窗口会隐藏应用；托盘不可用时关窗口会直接退出。「开机自启动」分别用 Windows 当前用户的 Run 注册表、Linux 的 XDG Autostart 和 macOS 的 LaunchAgent 实现，并以最小化方式启动；如果托盘初始化失败，会保留可见窗口。
- **Android**：开启自动接收或手机服务器后，会通过前台服务显示常驻通知，并在开机、应用升级、进程被回收后尽量恢复。网络恢复时会更新本机 IP 并立即重试。但如果用户手动强行停止应用、在系统界面里停掉服务，或被厂商后台冻结，就必须重新打开 FlowClip。

## 源码与发布

```text
desktop/              Windows、Linux、macOS 共用的桌面源码和原生打包脚本
android/              Android Gradle 工程
docs/                 协议、部署、构建、平台和隐私说明
THIRD_PARTY_LICENSES/ 完整第三方许可证与版权声明
.github/workflows/    CI、安全扫描和 Release 自动化
```

**开发环境要求**：桌面端需要 Python 3.11；Android 需要 JDK 17、Gradle 8.9、Android SDK Platform 35 和 Build Tools 35。Android 内置服务器使用 NanoHTTPD 2.3.1。依赖摘要见 [第三方依赖声明](THIRD_PARTY_NOTICES.md)，完整原文见 [第三方许可证包](THIRD_PARTY_LICENSES/README.md)。

**关于发布流程**：推送形如 `v1.4.0`、且指向默认分支提交的标签后，Release 工作流会在 Windows、Linux、macOS 的原生 runner 上分别构建并验证，然后发布桌面产物、Android Gradle 工程、许可证包、SHA-256 校验和和构建来源证明。几点说明：

- 所有第三方 GitHub Actions 都固定到经过验证的完整提交 SHA。
- Release 会先以草稿形式上传全部资产，成功后一次性公开；不会覆盖已有的同名 Release，失败或取消时也只清理本次创建的草稿。
- PyInstaller 不能交叉生成其他系统的正式产物；Linux 和 macOS 的兼容性必须在各自原生环境验证。
- Release 不包含 Android 签名密钥，也不会把未签名 APK 当作正式安装包发布。
